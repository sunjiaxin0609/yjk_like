「新建空白工程」改动范围评估

yjk_like · 评估日期 2026-10-10 · 依据：源码逐行核实（GridMesh.h / Model.h / CommandStack.h / BuildOps.h / MainWindow.cpp / main.cpp / yjk.cpp）
结论：可做，且比预想的小。核心层约 80% 的能力已经存在——Model 支持空构造、 GridMesh 是完整可独立调用的纯 C++ 轴网生成 API、CommandStack（撤销/重做）、 modelToYjk（另存为 .yjk）与 View3D 拾取基础设施全部现成。 缺的只是三个 GUI 入口：① 文件菜单「新建」动作；② 空白模型的正确初始化链路； ③ 轴网生成对话框（或手动加节点工具）。

1. 目标定义

「新建空白工程」= 从 GUI 直接开始一个全新模型，不依赖任何已有 .yjk 脚本，完整闭环为：

文件 → 新建空白工程 → 生成轴网（对话框）→ 拾取增补构件（B/C/W/P/L，已实现） → 属性编辑（已实现）→ 撤销/重做（已实现）→ 另存为 .yjk（已实现）→ F5 计算（已实现）

即：补齐起点（新建 + 轴网），其余链路全部复用现有实现。

2. 现状核实（逐条代码依据）

2.1 缺：GUI 无「新建」入口

缺口文件菜单（apps/ui/MainWindow.cpp:259-271）只有 打开建模脚本 / 重新加载 / 另存为 .yjk / 导出，无「新建」。唯一加载路径是 openScript(path)（MainWindow.cpp:667）， 无脚本时 F5 会强制走示例文件（MainWindow.cpp:1009-1028）。

2.2 有：核心可空构造

现成Model() = default 与 Model::clear()（Model.h:673-676, 761）—— 空模型直接可用，不需要任何初始化脚手架。

2.3 有：轴网生成 API 完整（最大复用资产）

现成GridMesh 是无 Qt 依赖的纯 C++ 类， ModelScript.cpp:742-908 的 grid.* 命令全部是对它的直接调用。已具备：

  • 轴线：addAxisX(y) / addAxisY(x) / addStory(z)
  • 构件事项：setColumn / setBeamAlongX/Y / setSlab / setWallAlongX/Y
  • 剖分：setDivX / setDivY（梁板节点天然重合的机制已内置）
  • 生成：generate(Model&) 一步产出节点/单元； 返回 Result，失败带可读诊断（现有 63 项测试覆盖）
  • 刚性楼板：addRigidDiaphragms 可直接调用

2.4 有：撤销/重做、序列化、拾取全部现成

3. 改动范围（三档方案）

方案 A：最小可行（新建入口 + 空模型初始化）—— 约 0.5 人日

改动：MainWindow.cpp/.h 新增「新建空白工程」动作：

  • 生成 make_unique<Model>() 空模型；
  • 依次调用现成重置链：clearResults() → cmds_->clear() → updateCmdState() → publishModel() → view_->frameAll() （与 MainWindow.cpp:689-700 打开新文件后的复位逻辑等价）；
  • scriptPath_ 置空、状态栏提示"空白工程"。

局限：若无「加节点」工具，B/C/W/P/L 在空模型上无处下手——需要叠加 View3D 新增 BuildTool::Node（点空白处放一个节点，用现有 unproject 射线定坐标）。 该档单独不构成完整闭环，宜与方案 B 合并实施。

方案 B：推荐（A + 轴网生成对话框）—— 约 2～3 人日

改动：

  1. 新文件 apps/ui/NewProjectDialog.{h,cpp}：输入轴距（X/Y）、层高、材料/截面名、板厚、剖分数、是否生成柱/梁/板/墙；
  2. 对话框「确定」后构建 GridMesh：addAxisX/addAxisY/addStory → setColumn/setBeam/setSlab → generate(model)， GridMesh 与测试零改动（纯复用）；
  3. 生成结果入撤销栈：cmds_->push(before, after) 一次快照即可「撤销轴网」；
  4. 后续用现有 B/C/W/P/L 工具在节点上增补/编辑。

收益：一条命令完成"新建 + 搭骨架"，闭环完整；复用 GridMesh 63 项成熟测试， 新增风险集中在纯 GUI 层。

方案 C：增强（向导 + 手动加节点 + 网格吸附）—— 约 5人日+

在 B 之上：① 轴网对话框支持随时修改轴线后续增量重建；② View3D 新增"放节点"工具与 轴线/交点吸附；③ 空模型拖拽建模。改动横跨 View3D 事件与 GridMesh 增量接口， 建议作为后续迭代，不在首版范围。

4. 建议的路线落点

当前路线：P4 规范验算与配筋（进行中）P5 工程化。

建议：以 「P4 并行小里程碑 · P4-D1 交互建模闭环补全」 立项，理由：

  • 与 P4 解耦：不触碰验算/配筋数据流，无依赖冲突，可并行；
  • 收益前置：P4-T5 配筋实配需要「工程师能从空白建出真实工程」做验收载体验证， 空白建模恰是前置条件；
  • 风险可控：核心全部复用，改动集中在 GUI 一层，回归只需 1 条端到端用例 （新建 → 轴网 → 增补 → 另存 → run），与现有 23 个测试目标互不干扰。

里程碑划分（每步独立可验收、单独 commit）：

  1. D1-1 新建空白工程：菜单动作 + 空白初始化链路（复用 §2.4 重置链），0.5 人日；
  2. D1-2 轴网生成对话框：NewProjectDialog 调 GridMesh 生成 + 撤销入栈，1.5～2 人日； 验收：新建后直接 F5 可算出结果，Ctrl+Z 可撤销整个轴网；
  3. D1-3 端到端用例：ui 无头脚本新场景 （--script 内建空白 → 生成 → run），并入现有 ctest，0.5 人日。

5. 风险与注意

  • 空模型直接 F5：现有 onRun 无模型时会弹示例选择—— 加入空白工程后需区分「从未打开过」与「刚新建空白」，建议新建时给 scriptPath_ 标记空态，F5 直接走空模型求解（提示"无约束/无荷载"由现有 check 给出即可）。
  • 另存为 .yjk：空/半成品模型经 modelToYjk 会输出 node/beam/shell （显式节点式脚本），可正常回读——已确认该路径存在；需补一条 「新建设计 → 另存 → 重新打开」回归用例。
  • 材料/截面引用：轴网对话框若由用户自定义材料名，需与 ModelScript 的 material/section 解析保持一致 （对话框可直接生成等价脚本命令再复用 ModelScript，减少双实现）。

6. 结论

「新建空白工程」对 yjk_like 属于中低复杂度、低风险的需求：核心层已提供 空模型、轴网生成、撤销重做、序列化四大现成能力，GUI 层只缺 2～3 个入口。 按方案 B 实施约 2～3 人日，可作为 P4 并行小里程碑推进；首版不做 手动加节点/网格吸附（方案 C），留待后续增强。

—— 本报告所有"现成/缺口"判断均基于当前源码（2026-10-10）逐行核实； 工作量为人日量级估算，未含跨平台回归成本。
